# 拟真人格微调训练方案（Phase 3 详案）：制作训练集、训练聊天模型

> **日期**: 2026-08-16（方案阶段，**未实施**，等拍板）
> **前置**: [persona_realism_training.md](persona_realism_training.md)（P38 prompt 侧拟真，已落地）
> **一句话**: P38 让模型"模仿"角色；微调让模型**权重里长出**角色的说话本能——更稳、更快、更省 token；事实知识仍交给 RAG。

---

## 一、为什么还要微调：P38 prompt 侧的天花板

P38（台词样本注入 + 内心反应 + 自检）实测已显著提升语气真实度，但它有三个天花板：

| 天花板 | 表现 |
|--------|------|
| **风格靠"模仿"而非"本能"** | 每次都要注入台词样本兜底，复杂/长对话仍会滑回模型的默认"助手腔" |
| **token 与延迟成本** | 样本注入 + 内心反应每次多花 ~60~120 token，上下文越长推理越慢、越贵 |
| **一模型侍 13 角色** | 所有角色挤在一个模型里，长上下文下性格互相干扰，破格要反复靠自检补救 |

**微调的本质**：把"像浮士德一样说话"写进模型权重。好处——语气稳定、破格率低、无需每次带样本、上下文更短更快；代价——要 GPU、要造数据、更新不如 prompt 灵活。

**结论**：不是替代 P38，而是**二阶增强**——先跑 prompt 侧（已就绪，零成本），验证效果后再上微调。

---

## 二、三条路线与推荐（关键决策）

### 路线甲：单角色专精模型（13 个模型）
- 每角色一个 LoRA/模型，最贴合，但训练/部署/更新 ×13，成本高。
- ❌ 不推荐作为主路线。

### 路线乙：多角色单模型 + 角色标记
- 一个模型，训练数据含全部 13 角色，通过 System Prompt 中的角色身份切换。
- 数据共享（角色间互动样本互相喂风格）、单一 vLLM 服务、一套 LoRA。
- 社区实证：Qwen3-4B 角色扮演 LoRA、[Qwen2.5-7B personas 微调](https://huggingface.co/maius/qwen-2.5-7b-it-personas) 等均为此路。
- ✅ 推荐为主路线（后期）。

### 路线丙：风格微调 + 知识 RAG 双层（务实首选）
- **微调只学"说话方式"（语气/句式/情绪反应），事实知识继续走现有 RAG + 直答四件套**。
- 理由：微调模型的知识会过期、会幻觉（游戏更新快），而语气不会过期；双层各司其职是业界定式。
- 接入改动最小：把 `agent/core.py` 的 LLM 从 DeepSeek 换成本地微调模型，检索链路不动。
- ✅ **推荐先走丙，再叠加乙**（丙=单角色 LoRA 起步验证，乙=全角色合并优化）。

## 三、训练集设计（本方案核心）

### 3.1 数据源与产量（按优先级）

**数据源 1：真实剧情对话（现成，最高质量，主料）**
- 已有资产实测：**42,224 条**剧情台词、**24,149 对**异角色相邻对话、912 个剧情页面（单页最长 336 句连续对话）。
- 构造方法：按 4~8 句窗口在对话序列上滑动 → `(多轮上下文 → 该角色下一句台词)` 样本；相邻对天然自带"对方刚说了什么"。
- 场景元数据（章节/战前战后/活动）随样本保留，模型学会"什么场合说什么"。
- 产量估算：12 罪人 × 3k~8k 条 ≈ **40k~80k**。
- 示例（真实提取）：
  ```
  希斯克利夫：说什么乱七八糟的！全都干掉不就好了吗！
  浮士德：……请尽力而为，但丁。
  ```

**数据源 2：官方语音台词（309 条）**
- 场景（问候/战斗/胜负/对话）→ 台词单轮样本，教"情境反应"（赢了说什么、输了说什么）。

**数据源 3：合成多轮对话（LLM 生成，扩覆盖）**
- 以角色卡 + 真实台词为锚，让 DeepSeek 生成"用户提问 → 角色风格回复"多轮对，覆盖闲聊/观点/情绪触发等剧情里没有的场景（如"夸你""骂你""问现实问题"）。
- 必须过过滤（见 3.3），占比 ≤ 40%，防止风格漂移。

**数据源 4：真实用户语料回流（后期在线沉淀）**
- 群内实测中"被追问/被认可"的回复人工打标回流训练；数据越用越像。

### 3.2 样本格式（sharegpt，LLaMA-Factory 直接可用）

```json
{
  "system": "你是浮士德，边狱公司（LCB）的罪人。习惯以第三人称自称，理性、冷静、略带傲慢。",
  "conversations": [
    {"from": "user", "value": "我们这次输得可真惨。"},
    {"from": "assistant", "value": "我本就没抱什么期望。不过，不要对失败耿耿于怀——重新整理计划再试一次就好。"},
    {"from": "user", "value": "你不生气吗？"},
    {"from": "assistant", "value": "情绪无法提高胜率。浮士德只计算下一步的最优解。"}
  ]
}
```

- 真实剧情样本：`user` 段 = 对话窗口（对方台词/旁白），`assistant` 段 = 该角色真实台词；
- 多轮样本尽量 >3 轮，教"连续对话中的一致性"。

### 3.3 过滤管线（决定数据质量的 80%）

1. **去重**：文本级 + 模糊（Edit Distance）去重；
2. **长度过滤**：目标台词 6~200 字（剔除碎片与长独白）；
3. **复读控制**：目标句与上文相似度过高剔除（防模型学会复读）；
4. **质量打分**：复用 P30 `score_story_line`（态度词/信息量/互动）做阈值；
5. **评测隔离**：训练与评测按**章节**切分（同一章节不同时出现在两边），防数据污染；
6. **敏感词过滤**：复用 `utils/sensitive_filter.py`；
7. **角色一致性抽查**：LLM 抽检 5% 样本，标注"是否人设不符"做反馈。

### 3.4 数量目标（分阶段，先小后大）

| 阶段 | 规模 | 内容 | 用途 |
|------|------|------|------|
| M1 最小验证 | 单角色 ~3k 条 | 真实剧情为主 | 验证"微调有用"假设 |
| M2 全角色 | 12×5k = 60k | 真实剧情 + 语音 | 路线丙正式版 |
| M3 增强 | 12×10k = 120k+ | + 合成数据 + 用户回流 | 路线乙合并模型 |

参考量级：社区角色扮演 LoRA 普遍 10k~100k 条即有效（[Qwen3-4B roleplay LoRA](https://huggingface.co/rockerBOO/qwen3-4b-roleplay-lora)、[RPG roleplay 系](https://huggingface.co/Chun121/Qwen3-4B-RPG-Roleplay-V2)）。

## 四、训练方案

### 4.1 基座选型

| 基座 | 显存 | 中文 | 理由 |
|------|------|------|------|
| **Qwen2.5-7B-Instruct**（首选） | 24G（QLoRA 16G） | 强 | 生态最成熟、角色扮演 LoRA 先例多、本地可跑 |
| Qwen3-4B | 16G | 强 | 更省，够用但上限低 |
| Qwen2.5-14B | 48G/租卡 | 强 | 质量更高，成本翻倍 |

### 4.2 训练流程（两阶段）

**Stage 1 — SFT（模仿真实台词，主训练）**
- LoRA：`r=32~64, alpha=32, dropout=0.05`，目标模块 `q/k/v/o + gate/up/down`；
- 超参：`lr=1e-4（余弦衰减）`，`epochs=2~3`，`seq_len=4096`（多轮打包 packing），`grad_accum` 对齐全局 batch 32~64；
- **早停判据**：评测集 loss 不再降 + 台词复读率不升。

**Stage 2 — DPO/ORPO（偏好对齐，可选）**
- 正样本：真实台词/被认可的回复；
- 负样本：**破格回复**——直接复用 P38 一致性检测产出的破格样例 + LLM 生成的"角色绝不会说的话"；
- 目的：让模型学会"不说什么"（少破格、少 AI 腔、少越界），比只教"说什么"更稳。

### 4.3 工具链
- **LLaMA-Factory**（事实标准，支持 sharegpt 格式 / QLoRA / DPO / 多模态不用管）；
- 数据导出复用现有 [`scripts/build_persona_corpus.py`](../scripts/build_persona_corpus.py)（加一个 `--format sharegpt` 分支即可，管线已就绪）；
- 推理部署：**vLLM**（OpenAI 兼容接口 → 现有 `agent/core.py` 的 `base_url` 一改即接入）。

### 4.4 环境与成本量级（估算）

| 项 | 量级 |
|----|------|
| 训练数据 | 60k 条 ≈ 300~600M token |
| 7B LoRA SFT（1×4090 24G） | 约 8~20 GPU 小时（QLoRA） |
| + DPO | 再加 ~6~12 小时 |
| 推理 | 本地 vLLM 免费；7B INT4 单卡 4090 约 60~100 token/s |

## 五、与现有系统的集成（双层架构）

```
用户消息
  → 意图门控 / 直答四件套 / RAG 检索（知识，保持 DeepSeek 或切换均可）
  → 本地微调模型（风格：语气/句式/情绪反应）   ← 核心替换点
  → P38 破格自检（保留，规则级零成本）
  → 输出
```

- **接入点**：`config.yaml` `llm.base_url` 指向 vLLM 即可，检索链路一行不动；
- **prompt 精简**：微调后说话样本可减量（模型已内化风格），内心反应可保留或关闭（A/B 决定）；
- **双路灰度**：config 加 `llm.backup_url`（DeepSeek），本地模型异常时回落，跑 A/B。

## 六、评测方案（复用 + 新增）

1. **复用四维裁判**：`scripts/eval_persona.py` 直接对"DeepSeek prompt 侧（现状）" vs "微调模型"打分（性格/语气/情绪/边界）——同一套题，可横比 P38 效果；
2. **新增盲测**：同题两版回复（去标签）给真人投票选"更像"——LLM 裁判有噪声，真人票更可信；
3. **回归集固化**：按章节隔离的训练集对应评测集（防污染），每次微调后跑一遍；
4. **专项指标**：破格率（P38 规则计数）、台词复读率、知识边界保持率（微调后是否还守得住"不知道就说不知道"）。

## 八、风险与对策

| 风险 | 对策 |
|------|------|
| **过拟合复读台词** | 3.3 复读剔除 + 早停判据盯复读率；合成数据控制占比 |
| **知识幻觉/过期** | 双层架构——微调只学风格，事实永远走 RAG/直答（游戏更新快，模型知识必过期） |
| **数据污染致评测虚高** | 按章节隔离训练/评测集 |
| **风格漂移（合成数据引入 AI 腔）** | 合成数据以真实台词为锚 + 抽检 5% + 质量阈值 |
| **13 角色互相干扰（乙路线）** | 角色 System Prompt 硬锚 + 数据按角色均衡采样 |
| **合规** | 官方中文 Wiki 文本仅内部研究/学习用途（项目已声明免责），不上传公网 |
| **成本失控** | 严格走 M1→M2 门禁：单角色 3k 条验证无效就止损，不做全量 |

## 九、待你拍板的决策点

1. **路线**：先"丙（风格微调+知识 RAG）"还是直接"乙（多角色单模型）"？——我推荐丙起步。
2. **基座**：Qwen2.5-7B（24G 卡）还是 Qwen3-4B（16G 卡）？——7B 性价比最高。
3. **环境**：本地 4090 / 租卡 / 只先做数据管道（M1，无需 GPU，1~2 天可先跑）？
4. **范围**：先单角色（浮士德）最小验证，还是直接全角色？

> 我的建议路径：**M1 数据管道（无 GPU 即可做，先把 60k 训练集造出来）→ 单角色 3k 最小验证 → 门禁通过再全量**。数据是本方案的定海神针——我们已经有了 42k 真实台词 + 24k 对话对，这一步几乎是白赚的。
